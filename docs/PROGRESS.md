## 今回完了 — 車両確認と運行遷移のHTTP安全契約（2026-09-17・フィジー日付）

- `assigned -> arriving -> on_trip -> completed` を、認証済み担当運転手、期待版、Idempotency-Key、許可された隣接遷移で進めるHTTP受入を追加した。
- 利用者の車両確認は全角・空白・記号を正規化して予約ナンバーと照合し、成功時に依頼版を進め、その版だけに有効な確認として保存する。同一キーの再送では版・監査を増やさない。
- 成功後に別車両・別本人を確認した場合は以前の確認を破棄し、依頼版を進めて古い乗車開始を無効化する。生の観測ナンバーは監査イベントへ保存しない。
- 現在版に結び付く車両確認がない乗車開始は `409 vehicle_confirmation_required`。現在資格を失った担当運転手は `409 driver_unavailable` とし、依頼状態・版を変更しない。
- 車両確認／運行遷移の成功・拒否を既存の許可フィールドだけで監査記録し、正確な再送による重複がないことを検証する。

## 継続開発の進め方

- GitHubの最新PR・コミット・この文書を読み、別の作業が更新されていればその変更を引き継ぐ。
- 未完了の優先項目を一つ進め、意味のある検証を実行してから作業ブランチへ保存する。
- 実際に変更した内容、検証結果、未接続部分、次の一項目を記録する。変更のない報告だけのコミットは作らない。
- 既存のPRを更新し、競合時は他の変更を保持する。強制pushや無関係なファイル変更はしない。
- 本番統合・公開、実在の免許情報、課金を伴うAPI利用を、試作の完了と混同しない。公開の前に実際の接続・検証状態を確認する。
- ブラウザや接続の安全設定を回避せず、利用可能な判定テスト・設計・レビューを進める。
