## 追記（同日2回目）: Google登録連携と Google Maps 接続

ユーザー要望「利用者登録の Google 連携」「Google Maps API の反映」を追加した。

- **接続設定画面**（役割選択右上の「接続設定」）: Google OAuth クライアントID と
  制限付き Google Maps ブラウザキーを入力する。CLAUDE.md の方針どおり、
  キーはリポジトリ・URLクエリ・端末保存に置かず**実行中のメモリにのみ保持**
  （再読み込みで再入力）。
- **Google登録連携（利用者登録）**: クライアントID設定時に Google Identity Services の
  公式ボタンを表示。IDトークンから sub・メール・表示名だけをクライアント側で取り出し、
  フォームへ入力補助する。**これは認証ではない** — トークンの署名・aud・iss のサーバー検証、
  アカウント作成・ログインは未接続で、画面にもその旨を明記。壊れたトークン・不正な
  sub/メールは取り込まない（コアで検証、テストあり）。
- **Google Maps（配車タブ）**: キー設定時に実マップを読み込み、Nadi中心＋現在地
  （許可時）を表示。「料金を比較する」で行き先をジオコーディングして地図に反映。
  読み込み失敗・キー不正（`gm_authFailure`）・タイムアウトでは**略地図（デモ表示）へ
  正直に戻し**、失敗理由を案内。接続成功まで「接続済み」とは表示しない。
- 制約: claude.ai のプレビューページでは外部スクリプトが遮断されるため
  Google連携・実地図は動作しない（設定画面に明記）。ローカル起動（README）か
  リファラ制限付きキーでの自社ホスティングで確認する。実キーでのライブ検証は
  **未実施**（キー未提供のため）。Places オートコンプリート
  （PlaceAutocompleteElement）は実キー検証とあわせて次段階。

Issue #3「Claude実装: 最初に利用者/運転手を分岐し、登録情報から専用ホームへ遷移」の
**最初の成果物**として、以下を本リポジトリのルートアプリへ実装した。

- 役割選択（利用者 / 運転手）
- 利用者登録（表示名・国番号付き連絡先・任意メール・連絡言語・既定乗車地点・支払い希望・同意）→ 利用者ホーム（配車 / 車両確認 / 履歴 / 登録情報）
- 運転手3段階登録（本人・運転資格 → 車両・営業許可・名義人・営業範囲 → 確認書類・期限・同意）→ **審査待ちホーム**（ホーム / 依頼 / 運行 / 登録情報）
- 運転手は申請後も審査待ちのままで、受付開始・料金提示・迎車の操作はすべて無効。書類提出は承認ではない旨を画面に明記
- 登録途中の下書き自動保存と再読込後の復帰（この端末内のみ）
- URL直打ちで未登録のままホームへ入れないガード
- 端末保存に `approved` を書き込まれても読み込み時に審査待ちへ戻す（自己承認の禁止）

`docs/ROLE_SPLIT_AND_ONBOARDING.md` と `CLAUDE.md` のデザイン受入
（白/グレー基調・チャコール・控えめな緑・1.6px線画アイコン・44pxタッチ領域・絵文字/グラデーション/重い影なし・略地図はデモ表示と明記）に合わせ、
旧ルートアプリ（シアン基調・絵文字・混在メニュー）の `index.html` / `app.js` / `styles.css` を置き換えた。

## 起動方法

ビルド不要の静的ページ。次のどちらかで開く。

```bash
# リポジトリ直下で
python3 -m http.server 8000
# → ブラウザで http://localhost:8000 を開く
```

または `index.html` をブラウザで直接開く（file:// でも動作する）。
スマホでの確認は、会話で共有した claude.ai の非公開プレビューページ（所有者のみ閲覧可）からも可能。

各登録フォーム右上の「サンプル情報を入力する」で架空のサンプル値を一括入力できる。
登録データは端末の localStorage のみに保存され、「登録情報」タブの
「この端末の登録データをすべて消す」でやり直せる。
